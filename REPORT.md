## 2. Мета роботи

Метою лабораторної роботи є набуття практичних навичок створення Java-проєкту, організації його структури, налаштування Maven, використання системи контролю версій Git, автоматизованого тестування та безперервної інтеграції.

У результаті виконання роботи створено консольний застосунок «Кінотеатр», який зчитує CSV-файл, перевіряє коректність записів, обчислює статистичні показники та формує текстовий звіт.

Також налаштовано Maven Wrapper, JUnit 5, SpotBugs і GitHub Actions. Створено GitHub Issue, окрему гілку розробки та Pull Request. Опубліковано версію програми `1.0.0` із Git-тегом `v1.0.0`.

## 3. Постановка задачі

Відповідно до варіанта 19 необхідно реалізувати консольну програму для обробки інформації про кіносеанси.

Формат одного CSV-запису:

`film;hall;ticketPrice;sold;durationMin`

| Поле   | Тип    | Призначення  |
|--------|--------|--------------|
| `film` | String | Назва фільму |
| `hall` | int | Номер кінозалу |
| `ticketPrice` | double | Ціна квитка |
| `sold` | int | Кількість проданих квитків |
| `durationMin` | int | Тривалість фільму у хвилинах |

Необхідно визначити чотири підсумкові показники:

1. Кількість правильних і неправильних записів.
2. Загальний виторг від продажу квитків.
3. Середню ціну квитка.
4. Найбільшу кількість проданих квитків.

Програма повинна перевіряти правильність формату та значень полів. Некоректні записи необхідно враховувати окремо й не включати до статистичних розрахунків.

Результати потрібно виводити в консоль і зберігати в текстовому файлі у кодуванні UTF-8.

## 4. Структура програми

Проєкт організовано відповідно до стандартної структури Maven.

```text
LAB_KZP/

├── .mvn/
│   └── wrapper/
├── ai/

├── out/
│   └── .gitkeep
├── src/
│   ├── main/
│   │   └── java/
│   │       └── ua/

│   └── test/
│       └── java/

├── README.md
├── REPORT.md
├── mvnw

```

Основний клас програми — `ua.lpnu.kzp.Main`.

Файл `Main.java` містить логіку обробки аргументів командного рядка, читання CSV, перевірки записів, обчислення статистики та формування звіту.

Файл `MainTest.java` містить автоматизовані тести JUnit 5.

Файл `data/input.csv` використовується як приклад вхідних даних, а каталог `out/` призначений для результатів роботи програми.

Потік обробки даних:

1. Програма отримує аргументи командного рядка.
2. Визначає шляхи до вхідного та вихідного файлів.
3. Зчитує CSV-файл у кодуванні UTF-8.
4. Розділяє кожен запис на п'ять полів.
5. Перевіряє коректність значень.
6. Накопичує статистику лише для правильних записів.
7. Формує текстовий звіт.
8. Виводить результати та записує їх до вихідного файлу.

Підтримуються аргументи:

| Аргумент |    Призначення    |
|----------|-------------------|
| `--help` | Виведення довідки |
| `--version` | Виведення версії |
| `--input <path>` | Вибір вхідного файлу |
| `--output <path>` | Вибір вихідного файлу |

Стандартний вхідний файл — `data/input.csv`, стандартний вихідний файл — `out/report.txt`.

## 7. Приклади роботи

Для перевірки застосунку підготовлено файл `data/input.csv`, який містить десять записів: п'ять правильних і п'ять неправильних.

### Приклад правильних вхідних даних

```text
Дюна 2;1;180.00;120;166
Оппенгеймер;2;200.00;95;180
Інтерстеллар;3;160.00;150;169
Аватар 2;1;220.00;80;192
Матриця;4;150.00;110;136
```

### Приклад неправильних вхідних даних

```text
;2;180.00;50;120
Титанік;abc;170.00;100;195
Гладіатор;3;-150.00;80;155
Барбі;2;160.00;сто;114
Джокер;1;180.00;90
```

Наведені записи перевіряють порожню назву фільму, неправильний формат числа, від'ємну ціну, текст замість кількості квитків і відсутність одного поля.

Для розділення полів використовується:

```java
split(";", -1)
```

Значення `-1` дозволяє зберігати порожні поля, зокрема наприкінці рядка.

### Приклад запуску

```cmd
mvnw.cmd clean package
java -jar target/lab01-1.0.0.jar
```

### Підсумковий консольний вивід

```text
===== ЗВІТ КІНОТЕАТРУ =====
Правильних записів: 5
Неправильних записів: 5
Загальний виторг: 98700.00 грн
Середня ціна квитка: 182.00 грн
Максимальна кількість проданих квитків: 150
```

Програма також повідомляє про результати перевірки окремих записів, що дозволяє визначити некоректні рядки.

### Приклади помилкових ситуацій

- Порожня назва фільму — запис відхиляється.
- Значення `abc` замість номера кінозалу — помилка числового формату.
- Від'ємна ціна квитка — порушення умов валідації.
- Значення `сто` замість кількості квитків — помилка числового формату.
- Наявність лише чотирьох полів — неправильна структура CSV.
- Відсутність вхідного файлу — програма повідомляє про неможливість його прочитати.
- Відсутність шляху після `--input` або `--output` — аргумент командного рядка відхиляється.

### Вміст вихідного файлу

Програма формує файл `out/report.txt` у кодуванні UTF-8:

```text
===== ЗВІТ КІНОТЕАТРУ =====
Правильних записів: 5
Неправильних записів: 5
Загальний виторг: 98700.00 грн
Середня ціна квитка: 182.00 грн
Максимальна кількість проданих квитків: 150
```

Загальний виторг обчислюється як сума добутків ціни квитка на кількість проданих квитків для правильних записів:

`totalRevenue = Σ(ticketPrice × sold)`

Середня ціна квитка визначається як середнє арифметичне значень `ticketPrice` серед правильних записів.

Максимальна кількість проданих квитків визначається за найбільшим значенням поля `sold`.

## 11. Відповіді на контрольні питання

### 1. Яке призначення файла pom.xml?

`pom.xml` — основний конфігураційний файл Maven. У ньому описано проєкт, його версію, залежності, параметри компіляції, плагіни та правила збирання.

### 2. Чим відрізняються фази test, verify і package у Maven?

Фаза `test` запускає автоматизовані тести. Фаза `package` створює готовий артефакт, наприклад JAR. Фаза `verify` виконує перевірки, необхідні для підтвердження коректності зібраного проєкту. У стандартному життєвому циклі Maven фаза `verify` виконується після `package`, тому охоплює попередні фази.

### 3. Навіщо потрібен Maven Wrapper?

Maven Wrapper дозволяє запускати проєкт із потрібною версією Maven через скрипти `mvnw` і `mvnw.cmd`. Це зменшує залежність від того, яка версія Maven встановлена на конкретному комп'ютері.

### 4. Яку роль відіграє метод main?

Метод `main` є точкою входу до Java-застосунку. Саме з нього починається виконання програми, а масив `args` містить аргументи командного рядка.

### 5. Чим примітивний тип відрізняється від String?

Примітивні типи, наприклад `int` і `double`, зберігають прості значення. `String` є посилальним типом і представляє об'єкт, що містить текст та підтримує методи для роботи з ним.

### 6. Чому середнє потрібно обчислювати в double, навіть якщо сума й кількість мають тип int?

Якщо ділити два значення типу `int`, дробова частина результату відкидається. Використання `double` дозволяє отримати точніше середнє значення з дробовою частиною.

### 7. Що станеться, якщо Integer.parseInt отримати рядок "abc"?

Буде згенеровано виняток `NumberFormatException`, оскільки рядок `abc` не можна перетворити на ціле число.

### 8. Чому не можна мовчки пропускати рядок із помилкою?

Користувач повинен знати, що частина даних не була оброблена. Якщо пропускати неправильні рядки без повідомлення, підсумкові показники можуть виглядати правильними, хоча частину інформації втрачено.

### 9. Як String.split(";", -1) обробляє порожнє останнє поле?

Параметр `-1` зберігає порожні поля, зокрема останнє. Наприклад, рядок із роздільником наприкінці матиме додатковий порожній елемент у результаті розділення.

### 10. Чому для шляхів краще використовувати Path.of, а не "data\\input.csv"?

`Path.of` дозволяє працювати зі шляхами незалежно від операційної системи. Використання зворотного слеша як роздільника орієнтоване на Windows і може створити проблеми на Linux або macOS.

### 11. Навіщо явно задавати StandardCharsets.UTF_8?

Це забезпечує однакове кодування тексту незалежно від налаштувань операційної системи. Особливо важливо правильно зчитувати та записувати українські символи.

### 12. Чим %n відрізняється від \n у форматованому виводі?

`%n` використовує роздільник рядків поточної платформи. `\n` означає конкретний символ переходу на новий рядок.

### 13. Які дані потрібно перевірити у вашому варіанті?

Для варіанта «Кінотеатр» необхідно перевірити наявність п'яти полів, непорожню назву фільму, додатний номер залу, скінченну невід'ємну ціну квитка, невід'ємну кількість проданих квитків і додатну тривалість фільму. Числові поля повинні мати правильний формат.

### 14. Які тести виявлять помилку в обчисленні середнього?

Потрібні тести з кількома різними цінами, для яких заздалегідь відоме середнє. Корисно також перевірити один запис, порожній файл і набір із неправильними записами, які не повинні впливати на результат.

### 15. Яке призначення статичного аналізатора?

Статичний аналізатор перевіряє вихідний або скомпільований код без звичайного виконання програми. Він допомагає знаходити потенційні помилки, підозрілі конструкції та проблеми якості коду.

### 16. Яку роль виконує GitHub Actions?

GitHub Actions автоматизує збирання, тестування й перевірку проєкту після змін у репозиторії. У цій роботі він перевіряє програму на Ubuntu, Windows і macOS та публікує JAR-артефакти.

### 17. Що має містити GitHub Issue на дефект?

Issue повинен містити зрозумілу назву проблеми, опис ситуації, кроки для її відтворення, очікуваний та фактичний результати. За потреби додають повідомлення про помилки й інформацію про середовище.

### 18. Що Ви повинні вказати у розділі звіту про академічну доброчесність?

Необхідно зазначити, чи використовувався ШІ, назвати інструменти, описати власний внесок, ролі агентів, приклади промптів, прийняті рекомендації та виправлені помилки. Також потрібно підтвердити розуміння поданого коду й відповідальність за результати.

### 19. Яку роботу виконує агент DevOps, а яку – агент Валідатор?

DevOps допомагає з інфраструктурою: Maven, Maven Wrapper, конфігурацією збирання, CI та артефактами. Валідатор перевіряє коректність обробки даних, шукає крайові випадки й пропонує сценарії тестування.

### 20. Який рядок вашої програми найскладніше пояснити і чому?

Одним із найцікавіших для пояснення є використання `split(";", -1)`. Його особливість полягає в параметрі `-1`: без нього порожні поля наприкінці CSV-запису можуть бути відкинуті. Для валідації це важливо, оскільки програма повинна виявляти неповні записи, а не втрачати інформацію про їхню структуру.

## 12. Висновки

У результаті виконання лабораторної роботи створено консольний Java-застосунок «Кінотеатр» для обробки CSV-файлу відповідно до варіанта 19.

Програма перевіряє вхідні дані, розділяє правильні й неправильні записи, обчислює загальний виторг, середню ціну квитка та максимальну кількість проданих квитків, після чого формує текстовий звіт у UTF-8.

Під час роботи налаштовано Maven, Maven Wrapper, JUnit 5, SpotBugs, GitHub Actions, контроль версій Git і процес внесення змін через GitHub Issue та Pull Request. Створено версію `1.0.0` із Git-тегом `v1.0.0`.

Результати лабораторної роботи формують основу для лабораторної роботи №2, у якій функціональність можна розширити через створення окремих предметних класів, удосконалення структури програми та застосування принципів об'єктно-орієнтованого програмування.
