## 3. Формат вхідного CSV-файлу

Відповідно до завдання використовується CSV із заголовком:

```csv
film,hall,start,price,sold
```

Призначення стовпців:

| Стовпець | Тип Python | Опис |
|---|---|---|
| `film` | `str` | Назва фільму |
| `hall` | `str` | Ідентифікатор залу |
| `start` | `datetime` | Дата й час сеансу |
| `price` | `Decimal` | Ціна одного квитка |
| `sold` | `int` | Кількість проданих квитків |

Приклад:

```csv
film,hall,start,price,sold
Avatar,2,2026-10-20T18:00,150.0,100
Dune,1,2026-10-20T20:00,200.0,80
Interstellar,3,2026-10-21T16:30,180.0,120
```

Програма підтримує також україномовні назви стовпців Java-експорту:

```csv
фільм,зал,продано,час,ціна
```

Порядок стовпців може відрізнятися, оскільки значення отримуються за назвами полів через `csv.DictReader`.

Для правильного оброблення назв фільмів, що містять кому, використовується стандартне CSV-екранування:

```csv
"Spider-Man, No Way Home",1,2026-10-22T18:00,170.0,75
```

Порожній CSV, який містить лише заголовок, обробляється як порожній набір сеансів. Некоректна структура файлу або значення призводять до контрольованої помилки.

Файли відкриваються з параметром `newline=""`, щоб модуль `csv` самостійно обробляв завершення рядків. Кодування `utf-8-sig` дозволяє читати UTF-8-файли з маркером BOM.

## 4. Архітектура програмного застосунку

Проєкт організовано за принципом розділення відповідальності між модулями.

### `models.py`

Містить модель `Screening`, створену за допомогою `@dataclass(frozen=True)`.

Поля моделі:

- `film`;
- `hall`;
- `start`;
- `price`;
- `sold`.

Властивість `revenue` обчислює дохід одного сеансу:

```python
revenue = price * sold
```

Використання незмінної dataclass зменшує ризик випадкової зміни даних після їх завантаження.

### `errors.py`

Містить власний клас винятку `DataError`.

Виняток використовується для повідомлень про некоректні дані, зокрема з номером рядка та назвою поля.

### `loader.py`

Відповідає за читання CSV, визначення стовпців, перетворення значень та їхню перевірку.

Основні функції:

- `load_screenings()` — завантаження всіх сеансів у список;
- `iter_screenings()` — послідовне читання сеансів через генератор.

### `analysis.py`

Виконує аналіз завантажених даних.

Результати об'єднуються в модель `AnalysisResult`.

### `reporting.py`

Формує текстовий звіт і зберігає його у файл UTF-8.

### `cli.py`

Реалізує консольний інтерфейс через `argparse`.

### `utils.py`

Містить функцію, яка демонструє використання параметра за замовчуванням, `*args` та `**kwargs`.

### `streaming.py`

Надає інтерфейс доступу до генератора потокового читання CSV.

### `benchmark_memory.py`

Створює тестові набори даних і вимірює пікове використання пам'яті під час звичайного та потокового читання.

Модульна структура полегшує тестування окремих компонентів, повторне використання коду та локалізацію помилок.

## 5. Перетворення типів, колекції та comprehensions

Після читання CSV усі значення спочатку є текстовими.

Для подальшого аналізу виконуються перетворення:

```python
datetime.fromisoformat(value)
Decimal(value)
int(value)
```

Тип `Decimal` використано для ціни, оскільки він забезпечує точні десяткові обчислення та дозволяє уникнути характерних для `float` похибок представлення грошових значень.

У проєкті використовуються три основні колекції:

**Список (`list`)** — зберігає послідовність кіносеансів і результати фільтрації.

**Словник (`dict`)** — пов'язує ідентифікатор залу з його сумарним доходом.

**Множина (`set`)** — зберігає унікальні назви фільмів без повторень.

Для відбору сеансів застосовано list comprehension:

```python
selected = [screening for screening in screenings if screening.sold > threshold]
```

Для визначення унікальних фільмів використано set comprehension:

```python
unique_films = {screening.film for screening in selected}
```

Таким чином, реалізовано щонайменше два різновиди comprehension.

## 6. Функції з параметрами за замовчуванням, *args та **kwargs

У модулі `utils.py` реалізовано функцію `describe_screening()`.

Її сигнатура:

```python
def describe_screening(
    film: str = "Невідомий",
    *args: str,
    **kwargs: object,
) -> str:
```

У цій функції:

- `film` — параметр зі значенням за замовчуванням;
- `*args` — додаткові позиційні аргументи;
- `**kwargs` — додаткові іменовані аргументи.

Завдяки такій сигнатурі функцію можна викликати з різною кількістю додаткових характеристик сеансу.

Для функції написано чотири тести, що перевіряють використання параметра за замовчуванням, позиційних аргументів, іменованих аргументів та їхньої комбінації.

## 7. Фільтрація, агрегація та детермінованість

### Фільтрація сеансів

Користувач задає поріг продажів через `--threshold`.

За замовчуванням:

```python
threshold = 50
```

Умова відбору:

```python
screening.sold > threshold
```

Отже, при порогу 50 сеанс із 50 продажами не проходить фільтр, а сеанс із 51 продажем проходить.

### Обчислення доходу

Для кожного сеансу:

```python
revenue = screening.price * screening.sold
```

Дохід кожного залу дорівнює сумі доходів його відібраних сеансів.

Загальний дохід обчислюється підсумовуванням доходів усіх відібраних сеансів.

### Унікальні фільми

Назви фільмів збираються у множину `set`, тому повторення автоматично усуваються.

### Найпопулярніший сеанс

Найпопулярнішим визначається сеанс із найбільшою кількістю проданих квитків.

Для однозначності результату при однаковій кількості продажів використовується додаткове впорядкування за назвою фільму, залом і часом.

### Детермінованість звіту

Під час формування звіту дані, для яких порядок має значення, виводяться у визначеному порядку. Це забезпечує повторюваність результатів та спрощує автоматизоване тестування.

## 8. Оброблення помилок

Для перевірки даних використовується власний клас `DataError`.

Перевіряються:

1. Відсутність обов'язкових стовпців.
2. Неоднозначність назв стовпців.
3. Неправильна кількість полів у CSV-рядку.
4. Порожні обов'язкові значення.
5. Некоректний формат дати.
6. Некоректна ціна.
7. Від'ємна ціна.
8. Некоректна кількість продажів.
9. Від'ємна кількість продажів.
10. Помилки відкриття та читання файлу.

Для збереження першопричини помилки використовується механізм:

```python
raise DataError(...) from error
```

Він дозволяє пов'язати зрозуміле повідомлення про помилку вхідних даних із початковим винятком Python.

Консольний інтерфейс повертає:

- `0` — успішне завершення;
- `2` — очікувана помилка оброблення даних або роботи з файлом.

Це дозволяє автоматизованим системам визначати результат виконання програми.

## 9. Формування текстового звіту

Звіт формується модулем `reporting.py`.

Основні функції:

- `format_money()` — форматування грошових значень;
- `build_report()` — створення текстового представлення результатів;
- `save_report()` — запис результатів у файл.

Вихідний файл записується у кодуванні UTF-8 із завершеннями рядків `LF`.

Якщо директорії для звіту немає, програма створює її.

### Приклад результатів аналізу Java-експорту

Вхідні дані:

| Фільм | Зал | Продано | Ціна |
|---|---|---:|---:|
| Avatar | 2 | 100 | 150,00 |
| Dune | 1 | 80 | 200,00 |
| Interstellar | 3 | 120 | 180,00 |

Після оброблення з порогом `50` отримано:

**Дохід залу 1:**

80 × 200,00 = 16 000,00 грн.

**Дохід залу 2:**

100 × 150,00 = 15 000,00 грн.

**Дохід залу 3:**

120 × 180,00 = 21 600,00 грн.

**Загальний дохід:**

16 000,00 + 15 000,00 + 21 600,00 = **52 600,00 грн**.

**Унікальні фільми:** Avatar, Dune, Interstellar.

**Найпопулярніший сеанс:** Interstellar — 120 проданих квитків.

Згенеровані текстові звіти збережено у папці `reports/`.

## 15. Відповіді на контрольні запитання

### 1. Яку роль виконує pyproject.toml у Python-проєкті?

`pyproject.toml` є центральним конфігураційним файлом сучасного Python-проєкту. Він містить метадані пакета, вимоги до Python, налаштування системи збирання, залежності та конфігурацію інструментів, зокрема pytest і Ruff.

### 2. Навіщо створюється віртуальне середовище?

Віртуальне середовище ізолює залежності конкретного проєкту від глобально встановлених пакетів Python. Це допомагає уникати конфліктів версій та забезпечує відтворюваність середовища розробки.

### 3. Чому CSV-файл відкривається з newline=""?

Параметр `newline=""` передає керування обробленням завершень рядків модулю `csv`. Це особливо важливо для коректного читання CSV, у якому поля можуть містити перенесення рядків.

### 4. Які типи повертає csv.DictReader без додаткового перетворення?

`csv.DictReader` повертає записи у вигляді словників. Зазвичай ключами є рядкові назви стовпців, а значеннями — рядки. Числа й дати необхідно перетворювати окремо.

### 5. Чому split(",") не є коректним CSV-парсером?

Метод `split(",")` розділяє рядок за кожною комою, не враховуючи лапки та правила екранування CSV. Наприклад, назва фільму `"Spider-Man, No Way Home"` містить кому, але повинна залишатися одним полем.

### 6. Як відрізняються список, словник і множина?

Список зберігає впорядковану послідовність елементів і допускає повторення. Словник зберігає пари «ключ — значення». Множина зберігає унікальні елементи та зручна для усунення повторів.

### 7. Коли comprehension робить код зрозумілішим, а коли краще використати цикл?

Comprehension зручний для коротких операцій фільтрації або перетворення колекцій. Звичайний цикл краще використовувати, якщо оброблення містить складну логіку, кілька умов, обробку помилок або побічні ефекти.

### 8. Що містять *args і **kwargs усередині функції?

`*args` збирає додаткові позиційні аргументи в кортеж. `**kwargs` збирає додаткові іменовані аргументи у словник.

### 9. Чому змінний об'єкт небезпечний як значення за замовчуванням?

Значення за замовчуванням створюється під час визначення функції. Якщо це змінний об'єкт, наприклад список, його зміни можуть зберігатися між викликами функції. Зазвичай для таких випадків використовують `None` і створюють новий об'єкт усередині функції.

### 10. Як raise ... from error зберігає першопричину?

Конструкція `raise ... from error` створює явний зв'язок між новим винятком і початковою помилкою. Завдяки цьому під час налагодження можна побачити не лише зрозуміле повідомлення, а й технічну причину збою.

### 11. Чому завантаження, аналіз і запис звіту розділяються на модулі?

Розділення відповідальності спрощує розробку, тестування та супровід. Кожен модуль виконує окреме завдання, тому зміни формату звіту не повинні впливати на логіку читання CSV або аналізу даних.

### 12. Яку гарантію дає with під час роботи з файлом?

Конструкція `with` забезпечує виклик механізму завершення роботи контекстного менеджера після виходу з блоку, зокрема в разі винятку. Для файлового об'єкта це означає коректне закриття файлу.

### 13. Чому звіт має формуватися в детермінованому порядку?

Детермінований порядок забезпечує однаковий результат для однакових вхідних даних. Це спрощує порівняння звітів, автоматизоване тестування та пошук помилок.

### 14. Які випадки повинні бути перевірені для порожнього CSV?

Потрібно розрізняти файл із коректним заголовком, але без записів, і файл без необхідного заголовка. Перший випадок може означати порожній набір даних, а другий — помилку формату. Також важливо перевірити поведінку аналізу та звіту для порожньої вибірки.

### 15. Чим тест поведінки відрізняється від перевірки внутрішньої реалізації?

Тест поведінки перевіряє результат роботи функції для заданих умов. Тест внутрішньої реалізації залежить від конкретного способу написання коду. Поведінкові тести зазвичай стійкіші до рефакторингу.

### 16. Які файли знаходить pytest?

За типовими правилами pytest шукає файли `test_*.py` та `*_test.py`, а всередині них — тестові функції й методи за відповідними правилами іменування. У цьому проєкті пошук тестів налаштовано на папку `tests`.

### 17. Які перевірки виконує Ruff?

Ruff виконує статичний аналіз Python-коду, виявляючи порушення вибраних правил, наприклад зайві імпорти та проблеми стилю. Ruff також має окремий інструмент форматування, який перевіряє або змінює оформлення коду.

### 18. Які коди завершення має CLI для успіху та очікуваної помилки?

У реалізованій програмі код `0` означає успішне виконання, а код `2` — очікувану помилку даних або роботи з файлом. Це дозволяє іншим програмам і CI визначати результат запуску.

### 19. Чому в CI запускаються і тести, і аналізатор, і пакетування?

Ці перевірки контролюють різні аспекти якості. Тести перевіряють поведінку програми, Ruff — якість і форматування коду, а пакетування — можливість створити встановлюваний дистрибутив. Разом вони забезпечують ширшу перевірку проєкту.

### 20. Які дані та результати потрібно задекларувати в REPORT?

У звіті необхідно зазначити тему, варіант, середовище розробки, формат вхідних даних, архітектуру, основні алгоритми, оброблення помилок, приклади результатів, тести, перевірки Ruff, пакетування, CI, GitHub Issues та Pull Request, використання ШІ, додаткові завдання й підсумковий висновок.
