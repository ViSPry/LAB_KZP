**Дисципліна:** Конструювання захищеного програмного забезпечення (КЗП)

**Мова програмування:** Python 3.11+  
**Репозиторій:** https://github.com/ViSPry/LAB_KZP  
**Робоча гілка:** `lab06`

## Опис проєкту

Цей проєкт є реалізацією лабораторної роботи №6 та продовженням системи кінотеатру, розробленої в попередніх лабораторних роботах мовою Java.

Python-застосунок призначений для завантаження, перевірки та аналізу CSV-даних про кіносеанси. За результатами оброблення формується текстовий звіт.

Програма підтримує стандартні англомовні назви стовпців, визначені завданням, а також україномовні назви, які використовуються під час експорту даних із Java-проєкту.

## Основні можливості

- Завантаження даних із CSV за допомогою `csv.DictReader`.
- Перевірка структури CSV та коректності значень.
- Перетворення дати й часу на `datetime`, ціни на `Decimal`, кількості продажів на `int`.
- Відбір сеансів, у яких кількість проданих квитків перевищує заданий поріг.
- Обчислення доходу за кожним залом.
- Визначення унікальних назв фільмів.
- Обчислення загального доходу.
- Пошук найпопулярнішого сеансу.
- Формування текстового звіту у форматі UTF-8.
- Запуск із командного рядка.
- Автоматизоване тестування через pytest.
- Перевірка коду через Ruff.
- Збирання та встановлення wheel-пакета.
- Автоматичні перевірки GitHub Actions на Windows, Ubuntu та macOS.
- Додатково: потокове читання CSV через генератор і порівняння використання пам'яті.

## Вхідні дані

Основний формат CSV:

```csv
film,hall,start,price,sold
Avatar,2,2026-10-20T18:00,150.0,100
Dune,1,2026-10-20T20:00,200.0,80
Interstellar,3,2026-10-21T16:30,180.0,120
```

Значення стовпців:

- `film` — назва фільму, рядок.
- `hall` — ідентифікатор залу, рядок.
- `start` — дата та час початку сеансу у форматі ISO 8601.
- `price` — ціна квитка, невід'ємне десяткове число.
- `sold` — кількість проданих квитків, невід'ємне ціле число.

Також підтримуються заголовки Java-експорту:

```csv
фільм,зал,продано,час,ціна
Avatar,2,100,2026-10-20T18:00,150.0
Dune,1,80,2026-10-20T20:00,200.0
Interstellar,3,120,2026-10-21T16:30,180.0
```

Порядок стовпців визначається за їхніми назвами.

Для полів, які містять кому, використовується стандартне CSV-екранування:

```csv
"Spider-Man, No Way Home",1,2026-10-22T18:00,170.0,75
```

## Запуск програми

Приклад запуску з CSV, експортованим Java-застосунком:

```powershell
python -m kzp_lab06.cli --input ../out/storage-export.csv --output reports/cinema-report.txt --threshold 50
```

Альтернативний запуск через встановлену консольну команду:

```powershell
kzp-cinema --input ../out/storage-export.csv --output reports/cli-report.txt --threshold 50
```

Перегляд довідки:

```powershell
kzp-cinema --help
```

### Аргументи CLI

| Аргумент | Призначення |
|---|---|
| `--input` | Шлях до вхідного CSV-файлу, обов'язковий |
| `--output` | Шлях до текстового звіту, обов'язковий |
| `--threshold` | Поріг продажів, за замовчуванням `50` |

Умова відбору сеансів:

```python
sold > threshold
```

Тому за порогу `50` сеанс із 50 продажами не потрапляє до вибірки, а сеанс із 51 продажем потрапляє.

## Оброблення помилок

Для помилок вхідних даних використовується клас `DataError`.

Програма перевіряє:

- наявність файлу та можливість його прочитання;
- наявність обов'язкових стовпців;
- відсутність неоднозначних назв стовпців;
- правильність кількості полів у рядках;
- відсутність порожніх обов'язкових значень;
- коректність дати й часу;
- правильність ціни та кількості продажів;
- невід'ємність ціни й кількості продажів.

Повідомлення про помилку можуть містити номер рядка та назву поля.

Коди завершення CLI:

- `0` — успішне виконання;
- `2` — помилка вхідних даних або очікувана помилка роботи з файлом.

## Додаткове завдання: потокове читання CSV

Реалізовано генератор `iter_screenings()`, який повертає записи послідовно, не завантажуючи весь CSV у список.

Приклад використання:

```python
from kzp_lab06.loader import iter_screenings

for screening in iter_screenings("data/input.csv"):
    print(screening.film)
```

Для порівняння пам'яті використовується:

```powershell
python benchmark_memory.py --rows 10000
```

Для більшого набору:

```powershell
python benchmark_memory.py --rows 100000
```

За допомогою `tracemalloc` отримано такі результати:

| Кількість рядків | Звичайне читання | Потокове читання |
|---:|---:|---:|
| 10 000 | 3,29 MiB | 0,16 MiB |
| 100 000 | 31,43 MiB | 0,17 MiB |

Ці значення відображають пікову пам'ять, яку відстежує `tracemalloc`, а не повне споживання оперативної пам'яті процесом.

Потокове читання економить пам'ять під час послідовного перебору записів. Основна функція аналізу при цьому зберігає відібрані сеанси у списку, тому повністю потоковий аналіз усіх результатів не реалізовано.
