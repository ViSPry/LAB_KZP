- Варіант: **19**

- Java: **21**

- Поточна версія: **1.0.0**

## Лабораторна робота №2

Тема лабораторної роботи №2 — **«Класи, record і інкапсуляція в Java-проєкті»**.

У лабораторній роботі №2 виконано рефакторинг програми з лабораторної роботи №1 без зміни її зовнішньої поведінки.

Основні зміни:

- створено предметний клас `Screening`;
- дані кіносеансу інкапсульовано у власному класі;
- поля `Screening` оголошено `private final`;
- валідацію перенесено до конструктора;
- реалізовано статичний фабричний метод `Screening.fromCsv()`;
- створено незмінний `record TicketSales`;
- статистичні показники передаються через `TicketSales`;
- реалізовано immutable Builder для `Screening`;
- Builder не може обійти перевірки конструктора;
- додано Javadoc;
- реалізовано `toString()` з використанням `Locale.ROOT`;
- збережено тести лабораторної роботи №1;
- додано нові JUnit-тести для предметної моделі;
- збережено попередні результати обробки контрольного CSV-файлу.

## Структура предметної моделі

Основні класи програми розташовані в пакеті:

`ua.lpnu.kzp`

### Main

`Main` є точкою входу до програми.

Клас відповідає за:

- обробку аргументів командного рядка;
- читання CSV-файлу;
- виклик `Screening.fromCsv()`;
- накопичення коректних об'єктів;
- обчислення статистики;
- формування консольного та текстового звіту.

### Screening

`Screening` представляє один кіносеанс.

Об'єкт містить:

- `film` — назву фільму;
- `hall` — номер залу;
- `ticketPrice` — ціну квитка;
- `sold` — кількість проданих квитків;
- `durationMin` — тривалість фільму у хвилинах.

Усі поля оголошені як `private final`.

Публічні сеттери відсутні, тому після створення стан об'єкта не змінюється.

Конструктор перевіряє інваріанти об'єкта. Некоректний `Screening` створити неможливо.

### Screening.fromCsv()

Статичний фабричний метод:

`Screening.fromCsv(String line)`

перетворює один CSV-рядок на валідний об'єкт `Screening`.

Метод:

1. перевіряє наявність рядка;
2. розділяє його на поля;
3. перевіряє кількість полів;
4. перетворює числові значення;
5. викликає конструктор `Screening`;
6. передає конструктору відповідальність за перевірку інваріантів.

### TicketSales

`TicketSales` реалізовано як Java `record`.

Він містить підсумкові значення:

- `validCount`;
- `invalidCount`;
- `totalRevenue`;
- `averageTicketPrice`;
- `maxSold`.

`record` використовується як незмінний допоміжний об'єкт-значення для передачі результатів обчислення статистики.

Compact constructor перевіряє коректність значень під час створення `TicketSales`.

## Додаткове завдання — immutable Builder

Для `Screening` реалізовано вкладений `Builder`.

Приклад:

```java
Screening screening = Screening.builder()
        .film("Інтерстеллар")
        .hall(2)
        .ticketPrice(180.0)
        .sold(150)
        .durationMin(169)
        .build();
